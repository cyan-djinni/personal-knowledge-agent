### Anthropic Engineering Blog

* **核心论点**：系统化拆解 AI Agent 的评估（Evals）设计方法，帮助开发团队告别盲目迭代与线上消防模式。
* **关键要点**：
  * Agent 评估复杂度远高于单轮 LLM 测试，因为 Agent 涉及多轮交互、工具调用及环境状态变更，错误会不断累积。
  * 构建评测三要素：任务环境（Environment）、评估集（Eval Set）与评估器（Graders），建议结合基于代码、基于模型与人工评估三种 Grader。
  * 区分能力评估（Capability Evals，目标通关率低）与回归评估（Regression Evals，要求近 100% 通关），能力测试成熟后应“毕业”转化为回归测试。
  * 编码 Agent 应优先使用确定性单元测试（如 SWE-bench）；复杂行为可使用 LLM Judge 并搭配人工定期校验。
* **值不值得深读**：极度值得深读，AI Agent 开发者建立工业级测试体系的最佳实践指南。
* 原文链接：https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents

* **核心论点**：介绍在 Claude Agent SDK 中构建长时长运行（Long-running）Agent 的双 Agent Harness 架构体系。
* **关键要点**：
  * 长期运行 Agent 的核心痛点是上下文窗口有限，单靠 Context Compaction 会丢失关键细节或导致 Agent 盲目冲动完工。
  * 采用双 Agent 模式：初始化 Agent（Initializer Agent）负责建立环境与拆解细化需求；编码 Agent（Coding Agent）负责单次专注实现单一功能。
  * 初始化 Agent 会生成强约约束的 JSON 格式需求清单（所有测试初始状态为 fail），防止后续 Agent 随意删除测试。
  * 要求 Agent 遵循工程规范：保持环境 Clean State、使用 git 提交并记录 `claude-progress.txt`，配合浏览器自动化工具（如 Puppeteer MCP）进行端到端测试。
