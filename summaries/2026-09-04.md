**Scaling Managed Agents: Decoupling the brain from the hands**
* **核心论点**：Anthropic 推出了 Hosted Managed Agents 服务，通过将 Agent 的推理大脑与执行工具、会话日志彻底解耦，构建可适应模型升级的长时序 Agent 架构。
* **关键要点**：
  * 传统单容器架构将 Agent Harness、沙盒与会话强绑定，容易因单点故障导致整个会话丢失，形成运维噩梦。

  * 针对长上下文丢失问题，提供 getEvents() 接口让 Agent 能以切片方式读取外部会话日志，实现灵活的回溯与重读。

### OpenAI Research

**How enabling two settings tripled our scores on the ARC-AGI-3 benchmark**
* **核心论点**：OpenAI 揭示了在 ARC-AGI-3 基准测试中，仅需开启 API 中的“保留推理”（Retained Reasoning）与“上下文压缩”（Compaction）两项关键设置，即可将 GPT-5.6 Sol 的得分提升三倍并减少 6 倍输出 Token。
* **关键要点**：
  * 原始评估 Harness 在每步操作后会清空私有推理过程（Thinking），并采用滚动截断（Rolling Truncation），导致模型在长流程游戏中遭遇“严重健忘”。
  * 通过 Responses API 传递上一轮 Response ID 以保留历史思维上下文，模型无需每步重复推理，战略连贯性大幅提升。
  * 使用 Compaction 替代截断，使得模型能在长达 175k 的上下文窗口中保留核心探索记忆。
  * 官方呼吁评测界避免使用丢弃推理信息的通用 Harness，评估应紧贴真实生产环境的配置。
* **值不值得深读**：非常值得深读，对大模型 Eval 评估机制、上下文工程与 Responses API 的最佳实践有极强指导意义。
* 链接：https://openai.com/index/how-two-settings-tripled-our-arc-agi-3-scores

**Separating signal from noise in coding evaluations**
* **核心论点**：OpenAI 深度审计了广泛使用的 SWE-Bench Pro 代码基准测试，发现约 30% 的任务存在严重设计缺陷，并宣布撤回此前采用该 Benchmark 的建议。
* **关键要点**：
  * 审计流程采用由 Codex 驱动的 Investigator Agent 配合资深软件工程师独立双轨复核。
  * 四大核心失效模式：测试过于苛刻（强制未约定的实现细节）、Prompt 描述不全、测试覆盖率低（残缺代码亦能通过）以及引导性误导 Prompt。
  * 强调开源 Repo 中的 Pull Request 往往伴随着人类的长期拉锯讨论，直接提取作为单步 Agent 测试会导致大量的评估噪音。
* **值不值得深读**：值得深读，揭示了当前大模型代码评估的深层困境以及利用 Agent 进行大规模 Benchmark 质量审计的全新路径。
* 链接：https://openai.com/index/separating-signal-from-noise-coding-evaluations

### Google Research Blog

**Transfer learning for genomic prediction in underrepresented populations**
* **核心论点**：研究评估了跨种族基因风险预测中的迁移学习效果，发现当目标人群样本量增加时，从欧洲人群数据集迁移学习反而可能降低预测准确率。
* **关键要点**：
  * 利用英国生物银行（UKB，欧洲人群）和日本生物银行（BBJ，日本人群）跨 8 种临床表型进行消融实验。
  * 当目标人群样本极小（<15,000）时，混合欧洲数据能带来显著统计提升；但样本量达到 15k 以上时，单一目标人群训练的模型效果反超。
  * 遗传保守性高的特征（如 BMI）能更长时间保留跨种族数据融合的益处，而代谢特征（HDL、LDL、血糖）由于人群特异性高，极易受到异质数据干扰。
* **值不值得深读**：中等推荐，生物信息学与多基因风险评分（PRS）领域的专业指南。

**Decoding the new AI lingo: Loops, harnesses, squads, hill climbing… oh my!**
* **核心论点**：GitHub 团队对当前 AI 软件工程中涌现的新概念（Loop Engineering、Harness、Squads、Hill Climbing 等）进行了系统性梳理与定义。
* **关键要点**：
  * **Loop Engineering**：围绕 Agent 建立可重复运行的系统（如 AI 驱动的 Cron Job），而非单次手动 Prompt。

  * **Harness Engineering**：构建和优化模型周围的工具、内存、上下文、权限及编排系统的工程学科。
  * **Hill Climbing**：利用 Eval 评估指标不断调整 Harness 和 Agent 提示词，实现系统效果梯次提升的过程。
* **值不值得深读**：非常值得深读，非常清晰地厘清了当下 AI 时代工程架构的关键新名词与底层逻辑。

**How we make AI coding more cost efficient without sacrificing task quality**
* **核心论点**：GitHub 揭示了在 Copilot CLI 中优化 Agent Token 成本的四大工程实践，强调单次工具调用的缩减不等于整体任务的降本。
* **关键要点**：
  * 局部优化陷阱：过度压缩单次终端输出（如使用 RTK 截断），常导致 Agent 因信息缺失反复重新读取，反而增加了总体 Token 消耗与耗时。
  * 选择性输出压缩：保留源码和任意脚本输出；重组搜索结果；仅压缩 Install/Build/Lint 等高冗余日志，并保留完整的恢复通道（Recovery Path）。
  * 格式精简：移除 `view` 工具展示代码文件时每一行自带的行号前缀，直接使模型推理成本下降了 5%，且无任何质量衰减。
  * Prompt 压缩：利用 Meta-Prompting 循环将 Agent 调度指令削减了一半，并精细微调防止其盲目并行。
* **值不值得深读**：非常值得深读，对研发大模型 Agent Harness 和 Token 控本的工程团队具有极高的实操借鉴意义。
* 链接：https://github.blog/ai-and-ml/github-copilot/how-we-make-ai-coding-more-cost-efficient-without-sacrificing-task-quality/

### AI & I by Every

「核心观点」——专业写作的未来不在于让 AI 直接生成文本，而在于通过精细的上下文工程构建“写作上下文环境”，让人类专注于提供不可替代的真实世界体验与关键判断。

**主讲人背景**：Katie Parrott（Every 资深撰稿人）与 Natalia Quintero（Every AI 咨询负责人）。

**核心洞见**：
* **把上下文当作栅栏**：写作前必须先将品牌定位、受众痛点、差异化观点等元数据整理成结构化文档。给 AI 搭建好“游乐场的栅栏”，生成质量才不会失控。
* **解决 AI 写作的“最后一公里”**：大模型拥有知识截止日期且缺乏物理体验，人类作者的核心价值在于补充截止日期之后的最新数据，以及独家的现实生活经历。
* **利用 Agent 突破写作瓶颈**：通过专用的微型工作流插件，将长文章拆解为确定性步骤，人类仅在关键节点做审查与定向，可实现一人媲美整个内容机构的产出。

> "Clarity doesn't arrive gift wrapped from a digital assistant. It's something I had to dig out for myself, question by question and prompt by prompt."
