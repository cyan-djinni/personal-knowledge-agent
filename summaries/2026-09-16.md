OpenAI 在 Hot Chips 大会上公布了专为推理优化的自研芯片 Jalapeño，其能效比比 NVIDIA GB200/GB300 高出 1.5-1.9 倍，延迟大幅降低；同时《The Pragmatic Engineer》深度揭秘 OpenAI 内部已高度演进为基于 Codex 的“软件工厂”，不仅工程师日常大幅减少 IDE 使用，连财务、法务等非技术部门的 Codex 周使用率也突破 90%，展现了 AI 重塑企业组织与软件工程的终极范式。

**OpenAI 推出面向生命科学研究的专业大模型 GPT-Rosalind**
OpenAI 发布了针对生物学、基因组学与药物研发定制的前沿推理模型 GPT-Rosalind，并配备了集成 50 多种公共多组学数据库与计算工具的 Codex 插件。该模型在 DNA/RNA 序列到功能预测（表现超越 95% 人类专家）及复杂分子克隆协议设计上取得了重大突破，标志着生成式 AI 正在从通用对话加速深入到硬核科学探索的核心阵地。

#### Code execution with MCP: Building more efficient agents
* **核心论点**：通过在 Model Context Protocol (MCP) 中引入代码执行环境，大幅减少 Agent 在调取大规模工具和处理复杂数据时的 Token 消耗与延迟。
* **关键要点**：
  • 传统 MCP 客户端在上下文窗口中预加载所有工具定义，当工具数量达上千个时，会导致数十万 Token 的冗余开销。
  • 传统直接工具调用强迫所有中间结果（如数万字的会议纪要）多次流入流出模型上下文，极易超出窗口限制或产生复制错误。
  • 将 MCP 服务器呈现为代码 API（如文件系统目录），Agent 可按需读取工具类型定义并编写代码完成中间数据过滤与逻辑循环。
  • 实际案例显示，代码执行模式将处理复杂任务的 Token 占用从 150,000 降至 2,000，时间与成本降低了 98.7%。
* **值不值得深读**：非常值得深读，这是构建高效率、低成本企业级 AI Agent 的关键工程范式文章。
* 原文链接：https://www.anthropic.com/engineering/code-execution-with-mcp

#### Bypassing inference bottlenecks: Accelerating complex AI search with Retrieve-for-Train
* **核心论点**：推出 Retrieve-for-Train 框架，利用离线强化学习与轻量化扩散模型，绕过高昂的自回归推理“思考预算”，实现毫秒级高质量 AI 搜索结果生成。
* **关键要点**：

#### AI & I by Every (Podcast)
「核心观点」—— AI 写作的核心突破不在于直接生成成品，而在于通过“上下文工程”（Context Engineering）打造结构化的思维沙盒，将人类从重复消耗中解放，从而释放深层的创造力。

Every 资深撰稿人 Katie Parrott 与 AI 咨询主管 Natalia Quintero 展开深入探讨。Katie 分享了自己从 AI 怀疑论者转变为利用 ChatGPT 进行职业规划与高产创作的历程。她提炼出三大洞见：1. 提炼上下文比提示词更重要：在开始写作前建立包含受众痛点、品牌定位和竞争差异的结构化文档（Project/Context），比反复微调写作文风指令有效得多。2. 解决“最后一公里问题”：AI 拥有知识截止线，人类撰稿人的核心价值在于注入知识截止线之后发生的真实世界体验与实时洞察。3. 写作是澄清思考的手段：提示本身就是一种极具战略性的写作过程，AI 扮演的是思维外化与责任约束的角色。

> "One of my favorite things about writing is that I never know what I think until I write it down, but once I write it down it becomes obvious."
