#### How we built Claude Code auto mode: a safer way to skip permissions
• **核心论点**：Claude Code 推出的 Auto Mode 采用基于 Sonnet 4.6 的分类器代理人工决策，在解决“审批疲劳”的同时，为自主代码 Agent 搭建了安全防护网。
• **关键要点**：
  • 传统沙盒配置繁琐且破坏网络/主机访问，而 `--dangerously-skip-permissions` 完全无防护，实践中用户会无脑同意 93% 的权限请求。
  • 输入层采用探针扫描工具输出中的 Prompt Injection，并在 Context 中植入警告指示 Agent 锚定初始目标。
  • 输出层采用两阶段分类器：先经过快速单 Token 过滤，仅在触发风险时调用思维链（Chain of Thought）评估风险。
  • 分类器采用“推理盲”设计，仅看用户消息与工具调用，阻断 Overeager（过度热情）行为与凭证越权探索。
  • 划分 Tier 1（内置只读工具放行）、Tier 2（项目内部文件修改放行）与 Tier 3（越界 Shell/网络请求送分类器审计）。
• **值不值得深读**：AI Agent 开发者与 CLI 工具架构师必读。
• 链接：https://www.anthropic.com/research/claude-code-auto-mode

#### Harness design for long-running application development
• **核心论点**：结合 GAN 思想设计的“生成器-评估器”双 Agent 架构及上下文重置机制，成功打破了 Agent 在长程复杂编码与前端设计上的性能瓶颈。
• **关键要点**：
  • 传统单 Agent 在长任务中易产生“上下文焦虑”（Context Anxiety），过早收尾；完全重置上下文配合结构化 Handoffs 效果优于压缩（Compaction）。
  • 模型对自己生成的代码天然偏向正面评价，解耦独立的 Evaluator 并将其微调为苛刻审核者，能大幅提升迭代质量。
  • 提出前端四大评估维度：设计质量（Design Quality）、原创性（Originality）、工艺（Craft）、功能性（Functionality），大力惩罚“紫白渐变卡片”等典型 AI 俗套设计。
  • 评估 Agent 配合 Playwright 直接对生成页面进行截图与交互分析，将主观审美转化为可量化的迭代反馈。
  • 最终演化为 Planner-Generator-Evaluator 三 Agent 结构，支持多小时级的全栈应用自主开发。
• **值不值得深读**：强烈推荐，长程 Agent 架构设计的重磅参考指南。
• 链接：https://www.anthropic.com/research/harness-design-long-running-apps

#### Equipping agents for the real world with Agent Skills
• **核心论点**：Anthropic 推出 Agent Skills 规范，通过文件夹封装指令、脚本与资源，采用渐进式披露模式（Progressive Disclosure）无缝扩展 Agent 的专业领域能力。
• **关键要点**：
  • 每个 Skill 均为包含 `SKILL.md` 的目录，YAML Frontmatter 包含名称与描述，启动时仅加载元数据至 System Prompt。
  • 渐进式披露分为三层：首层元数据知会、第二层加载完整 `SKILL.md`、第三层根据需要读取关联文件（如 `forms.md`）。
  • 结合文件系统与代码执行，Skill 内置的可执行脚本可以确定性、低成本地解决 Token 生成不擅长的任务（如复杂排序、PDF 格式提取）。
  • 建议从真实任务失败处切入开发 Skill，保持结构可扩展，并站在 Agent 视角迭代命名与描述。
  • 提醒注意 Skill 的安全性，避免安装未经审计的第三方 Skill 引致数据外泄或恶意指令注入。
• **值不值得深读**：开发者在使用 Claude Code 构建复杂工作流时必读。
• 链接：https://www.anthropic.com/research/equipping-agents-for-the-real-world-with-agent-skills

#### Strengthening our defenses against distillation attacks
• **核心论点**：Anthropic 构建了多层防蒸馏防御体系，成功拦截了 90% 至 99% 的未授权模型能力提取，有效遏制了海外实验室的工业级知识产权窃取。
• **关键要点**：
  • 蒸馏攻击指攻击者通过海量虚假账号提取模型完整推理过程（Reasoning Transcripts）来训练小模型。
  • 披露部分海外实验室利用蒸馏技术提升开源模型攻防能力（如智谱 GLM-5.3 蒸馏网络安全能力，月之暗面 Kimi 请求被隐蔽转发）。
  • 推出“Preserved Thinking”技术，禁止新 API 账号修改历史 Context，阻断代理网络跨账号提取推理链。
  • 限制推理链仅对产生该请求的特定组织可见，并禁止早先薄弱安全模型读取新模型的推理输出。
  • 采用双阶段宪法分类器实时识别蒸馏提取 Prompt，为此放弃了大量来自蒸馏攻击者的非法付费流量。
• **值不值得深读**：精采必读，涉及模型安全、防抓取与 LLM 知识产权保护的技术典范。
• 链接：https://www.anthropic.com/research/distillation-defenses

• 主讲人 Diogo Almeida 曾为 OpenAI ChatGPT 联合发明人之一，现为 TypeSave 创始人兼 CEO，推出了引发行业轰动的 Jev 系列决策模型。
• 洞见提炼：
  • 传统大语言模型生成冗长文本主要是给人看的，但软件 Harness 调用 AI 时往往只需要高度确定的状态或枚举值；机器原生（Machine Native）的 API 必须摒弃对自然语言样式的执念。
  • 目前模型无法落地到会计等具体工作，原因不在于模型不够聪明，而在于缺乏能够与现有软件系统精准契合的可靠系统一（System 1）直觉决策层。
  • 批评了目前行业“包装包装 Prompt 就当壁垒”的现状，倡导开发者应当将业务逻辑留给软件系统，仅将 AI 作为微小的决策节点使用。
• 原文金句："What percentage of those calls going into the LLMs are actually meant for human consumption vs. computer consumption... Operating on bits is very different than operating on strings."
